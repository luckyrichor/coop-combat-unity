## A 段：建工程（约 1 h，你来）

### A1　开工前三件事

```powershell
cd E:\WorkPlan\coop-combat-unity
git pull --ff-only
git lfs install
```

`git lfs install` 是**每台机器一次性**的设置，没做过的话现在做。没装 LFS 就提交 `.fbx`／贴图／音频，事后补很麻烦。

> ⚠️ 已知偶发：这台机器上 `git pull` 因 TUN 代理抖动失败过两次，重跑即好。**别只看命令有没有报错**，`git log --oneline -1` 确认真的拉到了最新提交。

### A2　确认 Unity 版本

打开 Unity Hub（装在 `F:\Unity_Hub`，**不在** `C:\Program Files`）。确认 **2022.3.38f1c1** 在列表里。

**这个版本是 09-19 定下的，不要改。** Hub 里另外两个版本（6000.3.23f1 / 6000.6.0f1）不要用——建完工程再换版本代价极大。

### A3　新建工程

Hub → `New project` → 模板选 **3D (Built-in Render Pipeline)** → 版本选 2022.3.38f1c1。

**位置这样填**：

| 字段 | 填 |
|---|---|
| Project name | `game` |
| Location | `E:\WorkPlan\coop-combat-unity` |

工程会落在 `E:\WorkPlan\coop-combat-unity\game\`。

**为什么套一层 `game\` 而不是直接用仓库根目录**：Hub 会在 Location 下**新建**一个以工程名命名的目录，而仓库根目录已经存在且非空（有 `.git`、`AGENTS.md`、`docs\`）。套一层是最省事的做法，仓库的 `.gitignore` 和 `.gitattributes` 规则不受目录层级影响，照样生效。

> 如果 Hub 在这一步报错或行为和描述不一致：换个空目录（比如 `D:\tmp\game`）建好，再把里面的 `Assets`、`Packages`、`ProjectSettings` 三个目录整体移到 `E:\WorkPlan\coop-combat-unity\game\`。**只要这三个目录**，其余都是可重建产物。

模板选 3D (Built-in) 的理由：3C 手感、技能表现、联机同步都不依赖渲染管线，而 URP 会在材质和后处理上多出一堆与岗位考点无关的坑。**这条可以改，但只有现在改便宜。**

### A4　立刻设两项（**最重要的一步**）

工程第一次打开后，**在放任何资产进去之前**：

`Edit > Project Settings > Editor`

| 项 | 设成 |
|---|---|
| Asset Serialization → **Mode** | **Force Text** |
| Version Control → **Mode** | **Visible Meta Files** |

顺手再设一项：**Line Endings For New Scripts → Unix**（与仓库 `.gitattributes` 的 `eol=lf` 一致，否则每次跨机都是满屏假 diff）。

**为什么必须先设**：默认的二进制序列化会让 `.prefab` / `.unity` / `.asset` 变成不可读、不可 diff、不可合并的二进制块。等资产建起来再改，已有文件不会自动转换。

**怎么确认真的生效**（别只看 UI）：记事本打开 `game\ProjectSettings\EditorSettings.asset`，应该能**看到可读文本**，且含有：

```
m_SerializationMode: 2
m_LineEndingsForNewScripts: 0
```

`m_SerializationMode: 2` 就是 Force Text。如果这个文件本身打开是乱码二进制，说明没设成功。

> 同机的 `E:\Unity_project\unity-learning-journal` 已经是这套设置，可以对照抄。

### A5　建一个最小可跑场景

不用做美术，目标只是"能跑起来、能看出角色在动"：

1. 新建场景存为 `Assets/Scenes/Playground.unity`
2. 放一个 Plane 当地面（`GameObject > 3D Object > Plane`），Scale 拉到 5×1×5 左右
3. 放一个 Capsule 当角色占位（`GameObject > 3D Object > Capsule`），命名 `Player`，Position Y 设 1
4. 地面上再扔两三个 Cube 当参照物——**没有参照物就看不出移动手感**，这不是装饰
5. `File > Build Settings` → `Add Open Scenes`，把 Playground 加进去

### A6　首次提交并推送

```powershell
cd E:\WorkPlan\coop-combat-unity
git status
```

**先看一眼 `git status` 的输出**，确认：

- ✅ 有 `game/Assets/`、`game/Packages/`、`game/ProjectSettings/`
- ✅ `.meta` 文件跟着资产一起出现（漏提交 `.meta` 会让别的机器上引用全丢）
- ❌ **不该**有 `game/Library/`、`game/Temp/`、`game/Logs/`、`.csproj`、`.sln`

最后三类如果出现了，说明 `.gitignore` 没覆盖到，**先告诉我，别硬提交**——Library 目录几个 G，提交进去清理很麻烦。

```powershell
git add .
git commit -m "feat: Unity project skeleton with text serialization"
git push
```

## C 段：接起来、评手感（约 2–3 h，你来）

### C1　拉取

```powershell
cd E:\WorkPlan\coop-combat-unity
git pull --ff-only
```

Unity 会自动重新编译。Console 有红色报错先截图发我，**不要自己猜着改**。

### C2　在编辑器里接线

我会在推回的代码里附一份具体的接线说明（哪个脚本挂哪个物体、哪些字段要拖引用）。大致是：把角色脚本挂到 `Player` 上、给它加 `CharacterController` 组件、把相机设为跟随目标。

### C3　跑起来，评手感

按 Play，**你是唯一能判断"手感可用"的人**，这一步无法远程替代。至少走一遍：

- 前后左右移动，斜向移动速度是否和直线一致（不一致就是没做归一化，告诉我）
- 鼠标环绕相机，视角是否跟手、有没有抖动或延迟感
- 角色贴墙走、相机被墙挡住时的表现
- 起步和停下是否过于生硬或过于滑

**手感问题请具体描述**："转身太黏，像有 0.3 秒延迟" 比 "感觉不对" 有用一百倍。参数我可以调，但我看不见画面。
