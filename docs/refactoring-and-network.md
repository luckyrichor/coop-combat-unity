# M1–M3 实现与重构取舍（2026-10-13，Codex）

Unity 2022.3.38f1c1，Game/为实际工程，创建资产前已继承Force Text，Visible Meta Files已核对；所有.meta与场景文本入库。Editor Setup.Build生成可运行Combat场景，代码构建Windows独立程序。WASD移动、鼠标轨道相机、Space冲刺、F范围攻击；可以两个本地程序分别host/--join。

## 分层重构

- CombatModel：纯C#权威规则，归一化方向/每tick每玩家一次最新输入、序号拒重、技能范围/冷却与Health；不依赖MonoBehaviour、网络或场景对象。
- LocalTransport：回环UDP二进制协议，玩家身份由源端点分配；每tick最多64包，最多4玩家，服务器按固定步推进并广播不可变快照。恶意包长度/非有限值拒绝，不是账号鉴权或完整防作弊。
- SessionView：MonoBehaviour输入、第三人称相机、快照显示与插值、技能事件的可见表现；只呈现服务器结果，不直接修改权威血量。两个技能共用事件计数，当前可见球体仅占位表现，不是成品VFX。

最初如果输入、战斗、UDP和镜头都放在Update，无法单独验证规则或双端一致；拆纯模型后EditMode无需场景也能验证规则，PlayMode再验证输入→判断→位移/表现，独立程序检验传输。代价是快照显示有约20Hz采样延迟，没有预测/回滚；简化合作原型优先可解释权威语义，不把它叫成熟联机框架。

## 已验证

5项EditMode：归一化/洪泛同tick合并、冲刺冷却与范围攻击、序号/NaN拒绝、双UDP端同权威状态、快照副本隔离。1项PlayMode加载实际场景，验证Camera/角色与冲刺位移、范围攻击可见表现。Windows独立构建成功，两进程回环运行，共100个共同双玩家tick快照逐字段一致（位置、血量、事件计数）。原始NUnit XML与对照摘要见measurements/2026-10-13。

修正过测试框架包缺失、JSON诊断类未标Serializable（初版日志只有tick、不构成状态一致性证据）；最终两进程完整重新跑。PlayerBuild产物在.local/player不入仓库，源码/配置/资产可重建。

## 尚需人工体验 / 边界

M1的操作手感与画面观感需要在Windows编辑器或独立程序亲自体验；本轮按授权跳过这部分，不能将自动测试等同主观手感验收。M2/M3工程路径已验证，但无动画、声音、真实美术、多人跨机器公网、丢包重传/拥塞、断线重连、账号权限与恶意身份防护。端点名额不回收，重启会清空会话；测试只证明本次回环运行。不是可上线游戏。
